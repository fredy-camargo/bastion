Manual de Arquitecto de Bastión

Especificación técnica exhaustiva de la arquitectura cliente-puro offline, el pipeline criptográfico sobre Web Crypto API, el desglose módulo por módulo del código fuente, la justificación de decisiones frente a arquitecturas alternativas y la guía operativa para instalar y desplegar Bastión en producción.

Stack: React 19 + TypeScript 7 + Vite 8 + Tailwind v4 · Crypto: Web Crypto API nativa · Offline: Workbox PWA + CSP estricta

1. Visión general y topología del sistema

Bastión implementa una arquitectura Zero-Network, Zero-Knowledge, Client-Only. No existe backend de negocio, base de datos remota, telemetría ni dependencia de CDNs externas en tiempo de ejecución. Toda la superficie de ataque de red se reduce a servir activos estáticos inmutables una única vez para su precacheo mediante Service Worker.

Separación estricta de fronteras de confianza

  • Frontera Volátil (RAM): Contiene exclusivamente RamVaultSession (referencia a CryptoKey no extraíble + arreglo VaultEntry[] descifrado). Al llamar a lockVault(), el estado de React se establece en null, se purga el portapapeles y se desmontan todos los componentes con datos sensibles.
  • Frontera Persistente (Disco / IndexedDB / Archivos .bvault): Jamás recibe texto plano ni llaves derivadas. Únicamente almacena objetos EncryptedVaultEnvelope autenticados con etiqueta GCM de 128 bits.
  • Frontera Visual (DOM vs. Canvas): Los secretos nunca se montan como nodos de texto visibles ni en <input type="text">. La presentación visual atraviesa un <canvas aria-hidden="true"> efímero.

2. Diseño del protocolo criptográfico

El núcleo criptográfico reside en src/crypto/engine.ts y delega el 100% de las primitivas matemáticas a window.crypto.subtle y window.crypto.getRandomValues (implementaciones nativas en C++/Rust compiladas en el navegador con instrucciones AES-NI / ARMv8 Crypto cuando el procesador dispone de ellas).

Pipeline de derivación de clave (KDF en dos etapas)

Master Password (UTF-8 Uint8Array)
        │
        ▼  crypto.subtle.importKey('raw', PBKDF2, extractable=false)
        ▼  PBKDF2-HMAC-SHA512 (salt: 256-bit CSPRNG, iterations: 600,000) -> 256 bits
        │  [finally: passwordBytes.fill(0)]
        ▼  crypto.subtle.importKey('raw', HKDF, extractable=false)
        ▼  HKDF-SHA512 (salt: 256-bit, info: "BASTION-VAULT-AES256GCM-KEY-V1")
        │  [finally: intermediateBits.fill(0)]
        ▼
CryptoKey { algorithm: AES-GCM-256, extractable: false, usages: ['encrypt', 'decrypt'] }
  • Sin almacenamiento de verificador/hash: No guardamos ningún hash de la clave maestra para comprobar si es correcta. La verificación sucede intrínsecamente durante crypto.subtle.decrypt() mediante la etiqueta AEAD de 128 bits de AES-GCM. Si la clave falla, el navegador lanza DOMException(OperationError).
  • Vinculación criptográfica AAD: Antes de cifrar o descifrar se construye un bloque canónico de datos autenticados adicionales: BASTION_VAULT|v1|AES-256-GCM|PBKDF2-HMAC-SHA512+HKDF-SHA512|{iterations}|{salt}|{scope}. Esto previene ataques de degradación de parámetros (downgrade attacks) o manipulación del encabezado JSON del sobre.
  • Rotación obligatoria de Nonce (IV): Cada operación de guardado en encryptVaultWithKey() solicita 12 bytes frescos (96 bits) a crypto.getRandomValues(). Nunca se reutiliza un par (key, iv), evitando el colapso de confidencialidad e integridad inherente a la reutilización de nonces en GCM.
  • Limpieza de buffers intermedios: Los arrays mutables passwordBytes, intermediateBits, plaintextBytes y decryptedBytes se sobrescriben explícitamente con ceros (.fill(0)) dentro de bloques finally para minimizar su tiempo de residencia en el heap de JavaScript.

Generación aleatoria sin sesgo de módulo

En secureRandomInt(maxExclusive) se evita el error clásico de usar randomUint32 % N (que introduce sesgo cuando 232 no es múltiplo de N). Se calcula maxUnbiased = Math.floor(0x100000000 / maxExclusive) * maxExclusive y se descartan muestras fuera de rango (rejection sampling), seguido de una permutación Fisher-Yates criptográfica sobre la contraseña resultante.

3. Modelo de datos y esquema del sobre .bvault

Tanto el registro almacenado en IndexedDB como los archivos exportables .bvault comparten exactamente el mismo contrato tipado EncryptedVaultEnvelope definido en src/types/vault.ts: 

{
  "format": "BASTION_VAULT",
  "version": 1,
  "cipher": "AES-256-GCM",
  "kdf": "PBKDF2-HMAC-SHA512+HKDF-SHA512",
  "iterations": 600000,
  "salt": "<Base64 de 32 bytes (256 bits)>",
  "iv": "<Base64 de 12 bytes (96 bits)>",
  "scope": "local-vault | export-full | export-category",
  "updatedAt": 1795370400000,
  "ciphertext": "<Base64(AES-GCM(JSON(VaultPayload)) || Tag-128bit)>"
}

Antes de intentar derivar cualquier llave al importar un archivo externo, el validador de esquema isValidEnvelope() exige coincidencia estricta de format, version, cipher, kdf y un mínimo de iterations >= 100_000, rechazando sobres malformados o con parámetros debilitados.

4. Anatomía detallada del código (módulo por módulo)

index.html · vite.config.ts · src/index.css · src/main.tsx Capa de arranque, CSP y PWA offline

index.html establece la meta-política CSP default-src 'self'; connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'self' que bloquea peticiones a internet desde el motor del navegador. src/index.css importa las fuentes @fontsource/outfit, @fontsource/public-sans y @fontsource/jetbrains-mono para que Vite las empaquete localmente en dist/assets sin depender de Google Fonts. vite.config.ts configura VitePWA con manifiesto standalone, iconos 192/512/maskable y precacheo Workbox. src/main.tsx ejecuta registerSW({ immediate: true }).

src/types/vault.ts Contratos de dominio y valores iniciales

Centraliza las interfaces TypeScript para VaultCategory, VaultEntry, SecuritySettings, VaultPayload, EncryptedVaultEnvelope, PasswordGenOptions y EntropyReport, junto con las categorías iniciales y la configuración defensiva por defecto (30s portapapeles, 5 min auto-bloqueo, anti-OCR alto).

src/crypto/engine.ts Motor criptográfico puro (Web Crypto API)

Implementa deriveMasterKey, encryptVaultWithKey, decryptVaultEnvelope, createStandaloneEncryptedExport, isValidEnvelope, generateSecurePassword, calculateEntropyBits y generateUuid. Carece de estado global mutable y no interactúa con almacenamiento ni DOM, lo que facilita su auditoría aislada.

src/storage/indexedDb.ts Repositorio local de sobres cifrados

Envuelve la API asíncrona de IndexedDB en promesas tipadas (loadStoredEnvelope, saveStoredEnvelope, deleteStoredEnvelope) operando sobre la base bastion_encrypted_vault_db (store envelopes, clave única primary_vault). Cierra el handle de la base al completar cada transacción.

src/hooks/useClipboardGuard.ts · src/hooks/usePWAInstall.ts Hooks de integración de plataforma

useClipboardGuard encapsula navigator.clipboard.writeText con un respaldo controlado (textarea efímero aria-hidden que se vacía y elimina del DOM en el mismo tick si el iframe restringe la API asíncrona), gestiona el temporizador de cuenta regresiva con resolución de 250 ms y sobrescribe el portapapeles con "" al expirar o bloquear. usePWAInstall escucha beforeinstallprompt y detecta ejecución standalone o iOS Safari.

src/components/CanvasSecretViewer.tsx Renderizador aislado anti-DOM y anti-OCR

Dibuja los secretos directamente en un contexto 2D de <canvas aria-hidden="true" role="presentation"> escalado a devicePixelRatio. Mantiene el estado oculto (14 puntos fijos que no filtran la longitud real de la contraseña) hasta que el usuario mantiene pulsado el botón (onPointerDown / teclado). Mientras está revelado, redibuja cada 320 ms variando ruido de fondo, micro-rotación y desplazamiento vertical por glifo usando crypto.getRandomValues. Escucha blur y visibilitychange para limpiar el lienzo inmediatamente ante pérdida de foco.

src/components/SecureVirtualKeypad.tsx · PrivacyCurtainOverlay.tsx Entrada segura y ocultamiento de pantalla

SecureVirtualKeypad baraja dígitos, minúsculas, mayúsculas y símbolos mediante Fisher-Yates sobre crypto.getRandomValues, con opción de rebarajar tras cada clic para neutralizar ataques por mapa de coordenadas. PrivacyCurtainOverlay monta una barrera visual opaca con desenfoque sobre todo el viewport al pulsar Ctrl+Shift+P o al pasar la pestaña a segundo plano.

src/components/LockScreen.tsx · EntryInspector.tsx · ExportImportModal.tsx · SecuritySettingsModal.tsx · PasswordGeneratorModal.tsx Superficie de flujos de usuario

Componentes funcionales desacoplados que delegan toda persistencia y cifrado a callbacks de App.tsx. En ExportImportModal, la exportación con "Clave maestra en RAM" cifra directamente usando el objeto CryptoKey activo sin pedir ni almacenar la contraseña en texto plano; la exportación con "Clave dedicada" invoca createStandaloneEncryptedExport generando una sal nueva de 256 bits.

src/App.tsx Controlador de sesión en RAM y espacio de trabajo

Administra el ciclo de vida de RamVaultSession, el temporizador de inactividad, los atajos globales (Ctrl+Shift+L, Ctrl+Shift+P), la rotación de clave maestra (re-derivación con nueva sal + re-cifrado completo), el filtrado/ordenamiento reactivo en RAM y la limpieza en beforeunload.

5. Ingeniería de defensa contra agentes de IA y lectores de pantalla

Los agentes de navegador modernos (como extensiones basadas en árboles de accesibilidad o agentes multimodales que combinan inspección DOM + capturas periódicas) operan en dos vectores principales: extracción estructurada del DOM y reconocimiento visual OCR.

  • Vector 1 — Bloqueo de DOM y Accessibility Tree: El visor CanvasSecretViewer nunca coloca el secreto en texto interno, atributos title, aria-label ni data-*. El lienzo lleva aria-hidden="true" y role="presentation", bloquea contextmenu, dragstart y selección CSS (user-select: none). Incluso en estado enmascarado dibuja siempre 14 puntos fijos para no revelar la longitud real del secreto.
  • Vector 2 — Mitigación de OCR y captura pasiva: La exposición visual es estrictamente efímera (solo mientras el dedo o botón permanece presionado). Cuando se revela, se aplican tres perturbaciones calibradas para mantener legibilidad humana mientras degradan la segmentación OCR automática: (a) líneas y moteado de interferencia aleatorios por frame, (b) micro-desplazamiento vertical y angular independiente por carácter con refresco cada 320 ms, y (c) ocultamiento automático al perder foco la ventana o cambiar de pestaña.
  • Vector 3 — Mitigación de keyloggers de nivel DOM: El SecureVirtualKeypad inyecta caracteres directamente en estado React sin disparar eventos keydown de la contraseña sobre el campo de entrada y cambia el layout de teclas aleatoriamente.

6. Decisiones de arquitectura y análisis de alternativas (ADRs)

Decisión Arquitectónica Enfoque Elegido en Bastión Alternativas Descartadas y Por Qué
ADR-01: Motor Criptográfico Web Crypto API nativa (PBKDF2-SHA512 600k + HKDF + AES-256-GCM) con extractable: false. Librerías JS puras (CryptoJS, Forge): ejecutan aritmética sensible en el heap de JS exponiendo bytes de clave a volcados, carecen de aceleración AES-NI y añaden riesgo de cadena de suministro. Argon2 WASM: aunque resistente a ASIC/GPU, requiere memoria lineal WASM inspeccionable y binarios externos adicionales; 600,000 iteraciones de PBKDF2-HMAC-SHA512 cumplen la recomendación vigente de OWASP manteniendo cero dependencias criptográficas de terceros.
ADR-02: Empaquetado de Escritorio PWA Offline Standalone con fuentes empaquetadas y CSP estricta. Electron desde el inicio: empaqueta ~150 MB de Chromium + Node.js ampliando la superficie de ataque con acceso directo al sistema de archivos y ejecución de procesos. La PWA ofrece instalación directa en escritorio con sandbox nativo del navegador y puede envolverse en Tauri/Electron sin reescribir la lógica.
ADR-03: Persistencia Local Híbrido: IndexedDB (solo ciphertext) + archivos .bvault + Modo Efímero opcional. localStorage: síncrono, límite pequeño (~5 MB) y compartido de forma menos estructurada. Solo archivos manuales obligatorios: genera fricción alta en uso cotidiano y riesgo de pérdida accidental si el usuario recarga la pestaña; ofrecer Modo Efímero opcional da el máximo control a perfiles paranoicos sin penalizar al resto.
ADR-04: Validación de Clave Maestra Verificación implícita por etiqueta AEAD (GCM 128-bit) sin guardar hashes. Guardar hash salted de la clave maestra: crea un oráculo offline separado más barato de atacar y duplica superficie de verificación. Con AEAD, la integridad del sobre y la corrección de la llave se validan en un único paso atómico.
ADR-05: Renderizado de Secretos Canvas 2D efímero (Hold-to-Reveal) + ruido anti-OCR + teclado aleatorio. Input HTML con toggle type="password" ↔ "text": expone el valor en texto claro al DOM, al árbol de accesibilidad, a autocompletadores y a cualquier extensión o agente que inspeccione el documento.

7. Modelo de amenazas y límites honestos

Qué protege Bastión y qué queda fuera de su frontera

Protegido eficazmente: Robo físico del disco o respaldo .bvault (sin clave maestra), intercepción de tráfico de red (tráfico nulo), manipulación silenciosa de archivos cifrados (detección AEAD), lectura pasiva del DOM o árbol de accesibilidad por lectores de pantalla y agentes basados en DOM, persistencia residual en portapapeles y fuga de clave maestra hacia almacenamiento persistente.

Fuera de la frontera de cualquier aplicación en espacio de usuario: Un sistema operativo ya comprometido a nivel de kernel (rootkit / privilegios Ring-0), un volcado forense de memoria RAM física mientras la bóveda está activamente desbloqueada, o una cámara física externa grabando la pantalla mientras mantienes pulsado el botón de revelado. En entornos de riesgo extremo, combina Bastión con cifrado de disco completo (BitLocker / LUKS / FileVault) y un equipo dedicado sin red.

8. Cómo descargar, instalar y poner Bastión en producción

Al tratarse de una aplicación estática 100% autocontenida tras la compilación (dist/), poner Bastión en producción no requiere servidores de base de datos, contenedores complejos ni claves API. Sigue este procedimiento paso a paso:

8.1 Requisitos previos

  • Node.js 20 LTS o superior (incluye npm) únicamente en la máquina donde se compilará el paquete.
  • Navegador moderno basado en Chromium (Chrome, Edge, Brave), Firefox o Safari para ejecutar e instalar la PWA.

8.2 Descarga e instalación local del código fuente

# 1. Descarga o clona el repositorio del proyecto en tu equipo
git clone <URL_DE_TU_REPOSITORIO> bastion-vault
cd bastion-vault

# 2. Instala las dependencias exactas declaradas en package.json
npm install

# 3. Verifica tipos TypeScript (cero errores antes de compilar)
npm run lint

# 4. Ejecuta en modo desarrollo local (puerto 3000) para pruebas
npm run dev

8.3 Compilación del artefacto de producción

# Genera la carpeta optimizada y autocontenida dist/
# Incluye bundle JS/CSS, fuentes locales @fontsource, iconos PNG,
# manifest.webmanifest, Service Worker (sw.js) y manuales HTML.
npm run build

# Prueba local del build de producción antes de desplegar
npm run preview -- --port 4173 --host 127.0.0.1

Requisito de Contexto Seguro (HTTPS o localhost)

Por especificación de seguridad de los navegadores, tanto window.crypto.subtle (Web Crypto API) como el registro de Service Workers y la API del portapapeles requieren ejecutarse en un Contexto Seguro: esto es http://localhost / http://127.0.0.1 en local, o https:// con certificado TLS válido en red o servidor. No abras dist/index.html directamente mediante file://.

8.4 Opción A — Puesta en producción local en escritorio (100% offline / sin servidor público)

  1. Copia la carpeta compilada dist/ a una ruta fija en tu equipo (por ejemplo /opt/bastion o C:\Bastion).
  2. Sirve los archivos estáticos exclusivamente en la interfaz loopback local (127.0.0.1, inaccesible desde la red): 
    # Usando npx serve (o cualquier servidor estático ligero como Caddy o Python http.server)
npx serve -s dist -l tcp://127.0.0.1:4173
  3. Abre http://127.0.0.1:4173 en Chrome, Edge o Brave y pulsa Instalar app de escritorio.
  4. El Service Worker precacheará todos los activos. Desde ese momento puedes cerrar el servidor temporal si lo deseas o mantenerlo en segundo plano; la aplicación quedará instalada en el menú de aplicaciones del sistema.

8.5 Opción B — Despliegue en servidor propio (Intranet / HTTPS con Nginx)

Ideal para distribuir Bastión dentro de una red corporativa o servidor personal bajo HTTPS, aplicando cabeceras HTTP de endurecimiento en el servidor web. Copia el contenido de dist/ a /var/www/bastion y configura Nginx: 

server {
    listen 443 ssl http2;
    server_name boveda.tu-dominio.local;

    ssl_certificate     /etc/ssl/certs/bastion.crt;
    ssl_certificate_key /etc/ssl/private/bastion.key;
    ssl_protocols       TLSv1.3 TLSv1.2;

    root /var/www/bastion;
    index index.html;

    # Cabeceras de aislamiento estricto (defensa en profundidad)
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; worker-src 'self'; manifest-src 'self'; object-src 'none'; frame-src 'none'; frame-ancestors 'none'; media-src 'none'; base-uri 'self'; form-action 'none';" always;
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=(), usb=(), interest-cohort=()" always;
    add_header Cross-Origin-Opener-Policy "same-origin" always;
    add_header Cross-Origin-Resource-Policy "same-origin" always;

    # Nunca cachear el Service Worker ni el manifiesto en proxy/navegador
    location ~* ^/(sw\.js|registerSW\.js|manifest\.webmanifest)$ {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Activos con hash inmutables (JS, CSS, fuentes locales)
    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    # Manuales estáticos autónomos
    location ~* ^/manual-(usuario|arquitecto)\.html$ {
        try_files $uri =404;
    }

    # Fallback SPA
    location / {
        try_files $uri $uri/ /index.html;
    }
}

8.6 Opción C — Empaquetado nativo opcional para equipos Air-Gapped (Tauri)

Si tu organización requiere un binario nativo .exe / .dmg / .AppImage distribuible en equipos sin navegador autorizado, el directorio dist/ es directamente compatible con Tauri v2 apuntando frontendDist: "../dist" en tauri.conf.json sin modificar una sola línea de la lógica criptográfica, ya que el WebView nativo provee Web Crypto API, IndexedDB y Canvas 2D.

9. Lista de verificación antes de pasar a producción

  • 1. Cero tráfico externo: Abre DevTools → pestaña Network, recarga con caché limpia, crea una bóveda, genera contraseñas y exporta un .bvault. Confirma que el 100% de las solicitudes van al propio origen y 0 peticiones salen a dominios externos.
  • 2. Operación sin red verificada: En DevTools → Application → Service Workers, activa la casilla Offline y recarga la página. Bastión debe arrancar, desbloquear, cifrar y exportar sin errores.
  • 3. Inspección de almacenamiento en disco: En DevTools → Application → IndexedDB → bastion_encrypted_vault_db, comprueba que únicamente existe el registro primary_vault con campos salt, iv y ciphertext en Base64, sin ninguna cadena en texto plano. Verifica que localStorage y sessionStorage estén vacíos.
  • 4. Auditoría DOM de contraseñas: Selecciona una credencial, inspecciona el elemento del visor con DevTools y mantén pulsado Mantener para revelar. Confirma que la contraseña no aparece en ningún nodo HTML ni en el panel de Accessibility.
  • 5. Prueba de integridad AEAD: Exporta un .bvault, altera 1 carácter del campo ciphertext o del valor iterations con un editor de texto e intenta importarlo. Bastión debe rechazarlo inmediatamente con error de verificación AES-GCM.
